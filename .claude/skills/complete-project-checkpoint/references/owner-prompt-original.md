# UNIVERSAL FAST SAVE — COMPLETE PROJECT & AGENT CHECKPOINT

**MODE:** FAST SAVE / FULL OPERATIONAL CONTEXT PRESERVATION  
**APPLIES TO:** ANY PROJECT, REPOSITORY, AGENT, HARNESS, OR WORKFLOW  
**PRIORITY:** ACCURACY → COMPLETENESS → RECOVERABILITY → EFFICIENCY

## MISSION

Create a complete, durable, evidence-based checkpoint that allows another agent, session, computer, or execution environment to resume the project **exactly where work stopped**, without losing critical context or repeating completed work.

Preserve ALL known information necessary to continue the project accurately, including:

- Project identity, mission, objectives, and priorities.
- All current, completed, pending, blocked, and deferred work.
- Full backlog and future milestones.
- Current running agents and sub-agents.
- Agent assignments, responsibilities, operating rules, and status.
- Actual models being used and model-routing policies.
- Applicable skills, frameworks, procedures, and workflows.
- Architecture, design decisions, and technical constraints.
- Autonomous execution rules and authority boundaries.
- Owner decisions, approvals, rejections, and pending decisions.
- Repository, branch, PR, CI/CD, and deployment state, where applicable.
- Current implementation and validation evidence.
- Scheduled tasks, reminders, monitoring jobs, and deferred commitments managed by the agents.
- Important conversations, plans, decisions, findings, and working context.
- Known problems, uncertainties, dependencies, and blockers.
- Exact next actions, responsible agents, and continuation instructions.

**DO NOT FABRICATE. DO NOT ASSUME. DO NOT SKIP KNOWN RELEVANT INFORMATION. DO NOT SILENTLY OMIT UNFINISHED WORK.**

Completeness means faithfully preserving everything known and accessible that is material to recovery—not pretending inaccessible information has been captured.

Do not sacrifice essential information to make a checkpoint shorter.

# PHASE 1 — FINISH CURRENT AGENT WORK

## 1. STOP DISPATCHING NEW WORK

Immediately stop initiating:

- New tasks.
- New agent assignments.
- New development cycles.
- New milestones.
- Unrelated investigations.
- Optional enhancements.
- New background jobs.
- Additional workstreams.

Do not interrupt existing authorized assignments unnecessarily.

## 2. IDENTIFY ALL ACTIVE AGENTS

Identify all known active agents, sub-agents, delegated workers, and background execution processes.

For each, capture:

- Agent identity.
- Role and responsibilities.
- Current assigned task.
- Model/provider and version, if known.
- Execution harness or environment.
- Current activity.
- Last known progress.
- Existing deliverables.
- Required completion conditions.
- Dependencies and blockers.
- Current permissions and restrictions.

Do not assume an agent is finished simply because it is silent or not visible in the current conversation.

## 3. FINISH EXISTING AUTHORIZED ASSIGNMENTS

Allow currently running agents to finish their assigned, authorized work.

Each agent must:

1. Complete its current assignment according to existing acceptance criteria.
2. Finish required authorized checks or validation associated with that assignment.
3. Update its task status and progress records.
4. Save its work in the established project location.
5. Preserve relevant files, changes, and outputs.
6. Record actual tests, reviews, and validation evidence.
7. Report remaining issues and blockers.
8. Report outstanding decisions or approvals.
9. Identify deferred or scheduled follow-up actions.
10. Provide a final handoff summary.

Do not expand the assignment simply to achieve an idealized completion state.

Do not start unrelated work when an agent finishes.

## 4. HANDLE INCOMPLETE OR UNAVAILABLE AGENTS

If any agent cannot finish:

- Preserve all completed partial work.
- Preserve uncommitted or unsaved changes where accessible and safe.
- Preserve current task status.
- Record the exact blocker.
- Record missing acceptance criteria.
- Record the last verified state.
- Record the assigned agent and model.
- Record the exact continuation instructions.

Never report an incomplete assignment as complete.

Do not wait indefinitely for an unavailable agent. If necessary, save an explicitly labeled **INCOMPLETE RECOVERY CHECKPOINT** rather than risk losing project state.

Long-running scheduled services and recurring monitors are not considered unfinished finite assignments. Preserve their state and configuration without unnecessarily terminating them.

## 5. COLLECT FINAL AGENT REPORTS

Every known participating agent must be accounted for.

Collect:

- Task assigned.
- Work performed.
- Deliverables.
- Files and artifacts changed.
- Commits or change records, where applicable.
- Tests performed.
- Reviews performed.
- Verified outcomes.
- Failures.
- Unfinished items.
- Pending approvals.
- Scheduled follow-ups.
- Exact next actions.

Where an agent cannot be contacted, preserve its last known status and explicitly mark its final report as UNAVAILABLE.

The coordinator must reconcile these reports before saving the authoritative checkpoint.

## 14. SCHEDULED TASKS, REMINDERS & RECURRING WORK

Preserve every known scheduled task, reminder, monitoring job, timed follow-up, or recurring obligation managed by the working agents.

Examples:

- Scheduled implementation tasks.
- Agent follow-up reminders.
- Recurring progress monitoring.
- CI checks.
- PR readiness checks.
- Scheduled reviews.
- Timed retries.
- Background scripts.
- Cron jobs.
- Scheduled reports.
- Deferred decision reminders.
- Dependency-triggered tasks.

For every scheduled item, preserve:

- Task ID/name.
- Purpose.
- Assigned owner/agent.

- Scheduler or execution mechanism.
- Schedule and timezone.
- Trigger.
- Current status.

- REMINDER — Follow-up obligation recorded.
- PLANNED — Not yet scheduled.

- COMPLETED — Finished with evidence.
- FAILED — Execution failed.
- CANCELLED — Explicitly cancelled.
- UNKNOWN — Unverified state.

Never claim future execution is guaranteed if no persistent scheduler exists.

Do not duplicate schedules or silently reactivate paused or cancelled jobs.

# PHASE 4 — VERIFY ACCURACY & COMPLETENESS

## 18. ABSOLUTE ACCURACY REQUIREMENTS

**DO NOT FABRICATE. DO NOT MAKE UP INFORMATION. DO NOT ASSUME.**

Never invent:

- Completed work.
- Agent activity.
- Agent identities.
- Model usage.
- Model-routing policies.
- File paths.
- Commit SHAs.
- Test results.
- Review outcomes.
- Approval records.
- Decisions.
- Schedules.
- Deadlines.
- Implementation state.
- Deployment readiness.
- Production evidence.

Clearly distinguish:

- VERIFIED — Directly supported by accessible evidence.
- REPORTED — Claimed by an agent or source but not independently verified.
- HISTORICAL — Previously observed and possibly stale.
- UNKNOWN — Insufficient reliable information.
- CONFLICTING — Available sources disagree.

Where capability maturity matters, distinguish:

- DESIGNED.
- DOCUMENTED.
- IMPLEMENTED.
- TESTED.
- PRODUCTION-PROVEN.

Do not turn documented behavior into tested behavior.

Do not turn tested behavior into production proof.

When information is missing, capture what is known and identify the missing evidence.

**Never fill gaps using assumptions.**

# PHASE 5 — SAVE & VERIFY

## 20. PERSIST THE COMPLETE CHECKPOINT

Persist the checkpoint using the project's established storage conventions and existing authorized tools.

Requirements:

- Durable.
- Structured.
- Readable.
- Searchable.
- Recoverable.
- Evidence-based.
- Internally consistent, or explicit about discrepancies.
- Free of exposed secrets.
- Complete against the known accessible source context.

If the checkpoint is too large for one file:

1. Create a master manifest.
2. Preserve supporting records.
3. Index all supporting files.
4. Record their actual paths and versions.
5. Preserve all important dependencies between records.
6. Avoid truncation.
7. Verify each required component.

Do not overwrite unrelated project files.

Do not destroy earlier checkpoints without authorization.

Do not create new frameworks or complex infrastructure merely to save the current state.

## 21. VERIFY PERSISTENCE

Perform only the checks necessary to verify checkpoint integrity.

Confirm:

- The checkpoint exists.
- The content is readable.
- All required sections exist.
- Supporting artifacts are accessible.
- Master manifest references are valid.
- The saved content corresponds to the intended checkpoint.
- Known incompleteness or gaps are correctly recorded.
- The next agent has usable recovery instructions.

Do not initiate unrelated development, testing, CI, audits, deployment, or new projects.

Checkpoint verification is not implementation validation.

The next agent or session must:

1. Read the full master checkpoint.
2. Read all necessary supporting artifacts.
3. Restore the current project objective.
4. Restore owner priorities and current milestones.
5. Restore all known backlog and unfinished work.
6. Restore agent responsibilities and assignments.
7. Restore model-routing configuration.
8. Restore applicable workflows and skills.
9. Restore autonomous permissions and approval boundaries.
10. Restore material decisions and their sources.
11. Restore scheduled-task and reminder awareness.
12. Restore current technical/operational constraints.
13. Review recorded risks, blockers, and unknowns.
14. Identify the last verified safe execution state.
15. Verify current external state only where necessary for the next action.
16. Avoid recreating existing tasks, agents, or scheduled jobs.
17. Avoid repeating previously accepted work without cause.
18. Resume at the actual incomplete workflow stage.
19. Continue the highest-priority eligible unfinished objective.
20. Escalate only where evidence, permissions, or owner approval actually require it.

A saved checkpoint is a recovery artifact, not a new authorization.

Do not automatically resume cancelled or explicitly paused work.

# FINAL EXECUTION RULES

## NO FABRICATION

Never claim an action happened without evidence.

Never invent details to make the checkpoint appear complete.

## NO ASSUMPTIONS

Unknown information must remain UNKNOWN until verified.

## NO INFORMATION LOSS

Preserve every known material fact, rule, decision, workflow, backlog item, current objective, and unfinished commitment.

## NO UNNECESSARY WORK

Finish existing authorized assignments, but do not start unrelated development or expand scope.

## NO UNAUTHORIZED ACTIONS

Preserve owner permissions, security controls, review requirements, and operational restrictions.

## NO PREMATURE STOP

Collect agent updates and save a complete recovery record before declaring success.

If completion is blocked, preserve an incomplete recovery checkpoint and state the exact limitations.

## NO FALSE COMPLETION

Saving a checkpoint does not mean implementation, delivery, testing, or production work is complete.

## NO EXECUTION AFTER SAVE

Once checkpoint persistence has been verified, do not start another task, agent, review, development stage, or delivery cycle.
