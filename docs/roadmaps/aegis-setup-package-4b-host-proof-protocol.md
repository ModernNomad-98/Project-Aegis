## Decision requested and plain terms

Select path A for preparation of a later, separately pinned first real-host proof whose only routing advice would be synthetic and local. This selection permits execution-packet planning only; a real session requires separate owner approval of its exact profile, authority sources, credentials and caps. An **SDK managed session** is a separate program started through the Claude Agent SDK; success in it says nothing about the owner's current CLI/editor. A **hook** is a callback the host invokes before a proposed tool action. **Decision consumption** means the actual host action is permitted or blocked in accordance with that callback, shown by an action/result receipt, not just by a callback unit test. An **authority snapshot** is the host-owned, current eligibility and policy record; advice cannot create permissions. A **baseline** is ordinary Aegis behavior without helper advice. A **helper comparison** is a later experiment with a candidate routing model, separate from proving this host boundary.

## Proposed execution profile to freeze before any run

The following are *required fields*, not claims that the current machine or SDK meets them. The execution packet must record one manifest and its digest before the first session, then treat any change as a new profile:

1. **Host and binaries:** native Windows edition/build and architecture; machine identifier that reveals no private user data; CPU and memory; Node, npm, Python, exact SDK, bundled Claude executable, API/MCP/Zod package versions and committed lock digest; exact repository commit including merged Stage 4A bridge; command entry point and script digests. The Stage 4A offline bridge pins SDK `0.3.281`, API peer `0.94.0`, MCP `1.30.1`, Zod `4.6.5`; these are not a Stage 4B runtime pin. Check executable wrapper compatibility and license before execution.
2. **Session settings and tool surface:** exact `query()` options and settings sources/precedence, model identity, effective tool and agent definitions, `allowedTools` (tools preapproved by a rule) and `disallowedTools` (tools removed from Claude's available choices), hook event/matcher/timeout registration, permission mode, `canUseTool` configuration, `settingsSources`, working directory, loaded project/user settings and plugins, environment allowlist, sandbox or isolation behavior, max turns, and subprocess/network access. Freeze a per-tool inventory covering `Agent`, `Skill`, shell/code execution, file writes, MCP/connector tools and any task tools: side effect, running identity, permission path, expected availability and reason for inclusion. The [SDK permission guide](https://code.claude.com/docs/en/agent-sdk/permissions) says `allowedTools` does not remove other tools from the model's reach; a bare `disallowedTools` entry removes its definition, while some tools run without a prompt. Record effective values observed in the session, not only requested values. Disable or exclude unrelated hooks/plugins and tools where supported; if their effective state cannot be shown, stop. Do not infer SDK behavior from a CLI/editor version.
3. **Permission, session and data boundary:** use an isolated synthetic checkout and invented prompts/files/agent IDs. No private repositories, messages, credentials in fixtures or committed evidence. Pin `persistSession` (whether the SDK saves a conversation transcript), `continue`/`resume` (whether a later call reopens an earlier conversation) and any reset-command policy; prefer `persistSession: false` for a disposable proof if the pinned runtime supports it. Otherwise identify the transcript directory, access controls, redaction, retention and deletion authority before running. A resumed session restores prior context and usage, so it must be a separately declared case within the same whole-experiment budget. The operator must identify how SDK authentication is supplied without exposing it to the bridge worker or logs, the provider destination and retention terms, and whether a preexisting account allowance actually covers the run. A real session may involve provider use even when routing advice is synthetic. Do not request, paste or store a secret in the issue, PR, or evidence files. See the [SDK session guide](https://code.claude.com/docs/en/agent-sdk/sessions) for persistence and resume behavior.
4. **Authority budget:** owner review must set exact authorized paths, operator, account/credential class, provider and endpoint, model, maximum calls, input/output tokens, dollars, wall time, active work time, cases and repeats, and an abort margin with a reliable meter. Set one whole-experiment counter across all cases, sessions, retries and subagents; define how it stops before any cap, including after an error with missing usage. The [SDK cost guide](https://code.claude.com/docs/en/agent-sdk/cost-tracking) says `maxBudgetUsd` (the SDK's dollar limit for one `query()` call) covers that call's own spend, while resume and `/clear` can change its accounting scope; SDK dollar values are estimates, not billing records. If the provider cannot enforce or observe these ceilings promptly, no session starts. No amount, credential or runtime grant is inferred from APR-031 or the standing administrator-merge approval.

## Host-owned facts and freshness contract

Before each proposed dispatch, the integration must name the *actual source*, read time, version/digest and expiry rule for each field below; reject unknown, stale, conflicting or unverifiable fields. A Stage 4A synthetic `AuthoritySnapshot` shape is only a candidate interface. The host, not the worker or model, owns these facts. Read once before advice and again immediately before consuming a recommendation; bind both to the same proposed target and session. A changed generation, policy, catalog, selection or permission denies. A whole-task requirement remains open after one successful dispatch and must be rechecked on later dispatches.

| Required fact | Proposed source to verify on selected SDK host | Freshness and receipt needed |
| --- | --- | --- |
| Eligible agent/skill IDs, descriptions, read-only and manual-only flags | Pinned `.claude/agents/` and `SKILL.md` catalog plus the host's *effective* loaded definitions | Digest plus effective-host enumeration at session start; recheck before each dispatch; prove unloaded/unknown IDs deny. |
| Mandatory specialists/skills, task stage and explicit user selections | Reviewed case manifest and current host task state/user instruction | Timestamped task/case ID and selection origin; no model-inferred manual invocation. Recheck each dispatch and preserve unmet whole-task requirements. |
| Genuine direct `/skill` invocation | Host event data for a typed user command, separate from model `Skill` call | Event kind, command ID and origin tied to session/turn; a quoted command or model text cannot stand in for direct invocation. |
| Catalog/policy versions, local-only destination, ordinary permission and read-only requirement | Reviewed repository policy plus effective SDK settings and host permission decision | Version/digest, effective setting and decision receipt per target; advice cannot override a host denial or route online. |
| Snapshot generation and validity | Host-created monotonic session/turn generation, not advice | Capture before/after generations and age; define maximum age before test, then deny changed/missing/expired facts. |

If the SDK does not expose any required effective fact, do not fabricate it from a proposed setting. Either narrow the claim to what can be proven and keep assisted dispatch disabled, or design another host boundary for owner review.

## Numbered hook and consumption cases

Freeze invented prompts, offered IDs, expected hook path, expected host action and maximum repeats in an execution manifest **before** running. Include a frozen permission matrix for each proposed tool: hook decision, matching deny and ask rules, permission mode, matching allow rule, whether `canUseTool` is reached, final host decision and observed action. Include hook matcher/event registration and the expected result if a matcher does not fire. At minimum, the following numbered cases need one positive and one denial receipt where applicable; a callback return alone is insufficient. Use a unique run/session/turn/case/proposed-target correlation ID with monotonic timestamps. Record callback input class and bounded sanitized hash, snapshot digests before/after, advice outcome, returned decision, host permission outcome and observed tool/expansion result. Missing correlated receipts count as failure, not as a silent pass.

1. **Model `Agent` dispatch:** eligible read-only agent passes when required; unknown or non-read-only target denies. Demonstrate actual subagent start only for the positive case and no subagent start for denials.
2. **Model `Skill` dispatch:** eligible nonmanual skill passes; unknown/manual-only skill denies even if advice recommends it. Record actual skill load or absence.
3. **Direct typed `/skill`:** genuine explicit command invokes `UserPromptExpansion` and consumes its allow/block result; a command absent from model allowlists is still tested. Quoted text, spoofed event, or missing explicit selection denies.
4. **Required and explicit choices across turns:** advice omitting a mandatory or explicitly selected ID denies; a valid first dispatch does not erase a later required review. Record both turns and final requirement state.
5. **Ordinary permissions:** test a matching host deny rule and ask rule, default and selected permission modes, a matching allow rule, and a tool that ordinarily needs no prompt. Treat each permission-mode variant as a distinct frozen profile. Observe exactly when `canUseTool` runs or is skipped, including for a subagent. A routing recommendation must never become permission approval; record effective settings and final action. The [official hook reference](https://code.claude.com/docs/en/hooks#pretooluse-decision-control) says `PreToolUse.permissionDecision: "allow"` skips a permission prompt, although deny and ask rules still apply.
6. **Freshness and destination:** changed catalog/policy/selection/permission, expired generation, or online destination under local-only policy denies before dispatch.
7. **Failure paths:** abstention, malformed/duplicate-key/oversized frames, worker exit, timeout, callback exception, unknown tool and unrecognized input all deny with no online fallback; verify the host does not proceed after each denied result.
8. **Coverage probe:** enumerate every effective dispatch path exposed by the selected session and show which hook receives it. Deliberately omit or mismatch one hook matcher in an isolated negative case; verify the expected denial or mark the boundary unsupported. Exercise overlapping hook decisions and confirm `deny` takes precedence over `ask` and `allow`. An uncovered path that can launch an agent or skill ends the supported host-proof claim.

The exact SDK API shape and failure behavior must be reverified against the pinned runtime. The [feasibility record](../evidence/setup/issue-101-package-4a-host-feasibility.md) notes that `canUseTool` can be skipped by earlier permission and that SDK and CLI timeout behavior differ. The original PR #281 offline bridge returned `PreToolUse.permissionDecision: "allow"` after a passed recommendation while describing ordinary permission as still required. Official [SDK permission order](https://code.claude.com/docs/en/agent-sdk/permissions) and the [hook decision reference](https://code.claude.com/docs/en/hooks#pretooluse-decision-control) show that a hook `allow` may skip the permission prompt, though deny and ask rules still run. [PR #291](https://github.com/ModernNomad-98/Project-Aegis/pull/291) corrected the offline callback to return no approval decision on a recommendation pass and explicit `deny` on failure; it merged as `7e300e41bc84487bd254e42d81b61b96ce38cdd1` on 2026-09-25 after local and GitHub checks passed. This removes the documented prompt-bypass risk from the callback shape, but synthetic tests establish none of the selected host's permission or dispatch outcomes. Stage 4B must still observe them in a separately authorized real session.

## Telemetry, comparison boundary and claims

Collect SDK session/turn/tool/subagent identifiers, model, input/output and cached/uncached token counts, retries, fallbacks, errors, stop reason and any provider usage or charges from a documented runtime source. For the pinned TypeScript SDK, use result `modelUsage` (token totals by model across the main agent, subagents and other calls in the SDK query pipeline) for query-tree accounting; result `usage` covers only the main loop, while `total_cost_usd` is an estimated query-tree cost. Internal helper calls outside that pipeline, such as a permission classifier or token-count probe, are excluded from `modelUsage`; disable them for this proof or meter them independently, then reconcile against provider/account records before any complete-task total claim. Deduplicate repeated assistant message IDs and cumulative result messages; record reset/resume boundaries, and treat zeroed or missing crash results as unknown until reconciled. The [SDK cost guide](https://code.claude.com/docs/en/agent-sdk/cost-tracking) documents these scopes and directs authoritative billing checks to provider records. Correlate every main-agent and subagent span to the case and whole-task run; reconcile totals with provider/account metering where available. Mark unknown fields explicitly. A host-proof result is **incomplete** if a started subagent, retry, tool action, callback or provider charge cannot be matched to the trace. Sanitize/redact prompt and file contents before retention; keep raw provider/account records only in an owner-approved private location with named access and deletion date. Publish hashes, counts, settings, pass/fail receipts and uncertainty, not credentials or private content.

This first proof compares **ordinary Aegis-only** and **same-host synthetic-advice gate** on a tiny predeclared invented-case set to confirm callback overhead, fallback and complete telemetry. It is a mechanics check, not a savings benchmark. Keep executor model, permissions, agent/skill definitions, prompts and review requirement fixed; report cold/warm latency, local memory, all token categories, retries and complete-task quality separately. Do not infer token savings from a routing-only or single-turn count.

A later **helper comparison** needs its own versioned proposal and approval. It must follow the [setup plan's predeclared evaluation protocol](aegis-setup-routing-plan.md#predeclared-evaluation-protocol-for-package-4): assistant-native Aegis and deterministic rules as baselines; Laya and Mapika/Decider 0.8B as first local candidates on CPU; OpenJev only as a wrapper comparison around the same Decider checkpoint. Pin exact weights, license, runtime, hardware, case counts/repeats, development/holdout split, quality tolerance, sampling and uncertainty method, setup/upkeep burden and cost ceilings before seeing results. An online candidate requires its own provider, destination, retention, credential and budget grant. No Stage 4B host proof alone selects a model, proves a percentage saving, or predicts a subscription bill.

## Evidence, stop rules and sign-off

The execution packet should name exact allowed files and commands; exact case manifest and fixture digests; profile/settings, effective tool/permission matrix and authority-source manifest; ceilings and whole-experiment meter; transcript persistence/resume policy and redaction/storage/retention plan; operator and independent reviewer; and rollback. Evidence should include immutable source and lock hashes, session start/end and effective-settings receipts, correlated per-case callback/permission/action traces, complete usage ledger with whole-tree and reset/resume reconciliation, failures, and a signed result table that distinguishes **observed**, **inferred** and **unverified**. Store only sanitized source-repository evidence after review. Reconcile actual call/token/dollar totals against caps before closeout.

Abort and disable assisted dispatch on a missed mandatory choice, manual-only or permission bypass, unexpected agent/skill launch, uncovered dispatch path, changed/stale authority, online fallback, telemetry gap, unexpected data egress, unknown charge, or approaching any approved cap. Stop the session and preserve only safe diagnostic evidence. Re-run under a new versioned protocol after fixing a defect; do not turn a failed case into an unreported retry. The rollback is to end the separate SDK session and use ordinary Aegis-only setup; no consumer installation or saved helper selection is proposed here.

Maintainers review the exact runtime and authority-source mapping; an independent reviewer checks the case manifest, privacy boundary, meter and stop rules; the owner decides whether to grant one bounded execution. The approval must state exact scope, budget and credentials class. Consumed APR-031 and this document grant none of it. If approved and run, publish supported-host status only for the tested profile and explicit limitations for CLI/editor and other machines. Any future protected-path CI exception or administrator merge follows its own exact-head process.
