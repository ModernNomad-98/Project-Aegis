# Aegis Run Record v1: field and claim contract

Status: version 1, schema identifier `aegis.run-record/1` (matching the
`aegis.<slug>/<n>` convention). This document is the normative description of
the record and manifest that [the Aegis Run Record CLI](../../tools/aegis_run/cli.py)
writes. The machine-readable shape is [schema.json](schema.json), which
`verify` and `export` load and enforce; usage is in [README.md](README.md).

A record describes exactly one run of one application built with Aegis. It is
evidence of what was recorded and copied for that run, nothing wider.

## Run directory layout

| Path | Meaning |
| --- | --- |
| `D/aegis-run.json` | The record. Canonical form: UTF-8, sorted keys, two-space indent, LF, trailing newline. |
| `D/events.jsonl` | Append-only event log, one compact JSON object per line. Mirrors the record's `events` array in order. |
| `D/artifacts/<sha256-prefix>-<basename>` | Copied artifact bytes. `<sha256-prefix>` is the first 12 lowercase hex characters of the artifact SHA-256. |
| `D/manifest.json` | Export binding for the record and artifacts. |

## Record fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `schema` | string const `aegis.run-record/1` | yes | Record format and version. `verify` rejects any other value. |
| `run_id` | UUID string | yes | `uuid4()` generated by `init`; identifies this run attempt. |
| `app` | non-empty string | yes | Application name supplied by the operator. |
| `aegis_commit` | non-empty string | yes | The exact Aegis commit asserted for the run. Free text, not validated against a repository. |
| `host` | non-empty string | yes | Where the run happened, as supplied and unverified. |
| `model` | non-empty string or null | yes (key) | Model used by the builder, as supplied and unverified. A supplied value must be non-empty; `null` only when not recorded. |
| `created_at` | RFC3339 UTC string ending `Z` | yes | Local-clock initialization time. Not trusted time. |
| `events` | array of Event | yes | Mirrors `events.jsonl` exactly, in append order. The schema allows an empty list only for a newly initialized run; `export` and `verify` require at least one event. |
| `artifacts` | array of Artifact | yes | Copied artifacts plus any external references. |
| `outcome` | `delivered`, `stopped`, `failed`, or `null` | yes | `null` until `finish`. `export` and `verify` require a final value. |
| `limitations` | array of non-empty strings | yes | Stated scope limits. `init` starts it empty and the schema allows that only before finish (`minItems: 0`); `finish` and `export` require at least one entry, and `verify` rejects an exported record with none. |
| `owner` | string or null | no | Accountable owner, as supplied. `null` means not recorded. |

`owner` is the only optional key. All other keys above are always present in
records written by this CLI; `model` and `owner` use `null` when the optional
flags are omitted.

## Event fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `ts` | RFC3339 UTC string ending `Z` | yes | Local-clock time the event was appended. |
| `type` | `stage`, `approval`, or `note` | yes | Kind of event. |
| `stage` | non-empty string | yes | Stage label supplied by the operator, for example `1` or `build`. |
| `status` | `started`, `passed`, `failed`, or `skipped` | yes | Status of that stage entry. |
| `note` | string or null | yes (key present) | Free text, exported verbatim. |
| `actor` | string or null | yes (key present) | Who or what acted, as supplied. |
| `source_id` | string matching `^SS-[0-9]{3,}$` | no | Provenance of an imported project-state snapshot, for example `SS-003`. A string, never null or empty; accepted only when `actor` is `project-state-sync`; omitted on hand-written events. |

Appending an event writes one line to `events.jsonl` and then appends the same
object to `events` in the record. `events.jsonl` is never rewritten or
truncated by the CLI. A mismatch between the two is a verify failure.

### Project-state sync events

`sync` imports rows of the append-only `## State snapshots` table in a
project-state file. It reads that file and never writes it, and it is idempotent
by `source_id`: a row whose ID already appears in an event is skipped, so a
re-run appends nothing.

A snapshot records the stage the project is in when the row is written. It is
not evidence that a stage passed. Every imported event therefore carries
`status: started`, and `sync` never writes `passed` and never infers one.

| Import | Event |
| --- | --- |
| First import, all rows except the latest | `type: note`, `status: started`, note `historical snapshot SS-001 imported from project-state; not observed live` |
| First import, the latest row | `type: stage`, `status: started`, note `Imported from project-state; next: <next>` |
| A later sync, each new row | `type: stage`, `status: started`, note `Imported from project-state; next: <next>` |

Older rows are imported as notes rather than stages so that a first import does
not retrofit a run history that was never observed live. Only the newest row is
the current stage, and it is still only `started`.

`sync` holds an exclusive `D/sync.lock` (created with `O_CREAT|O_EXCL` and
retried for about five seconds) across the record read and every append. A lock
older than 120 seconds is never deleted automatically: the run fails, prints the
lock path, and asks the operator to remove it manually if no sync is running. One run directory has one
writer at a time; a second concurrent sync waits and then finds nothing new, so
it cannot duplicate a `source_id`.

The schema permits an empty `events` array only for a run that has just been
initialized. `export` and `verify` require at least one event, so a publishable
run needs at least one recorded event. `events.jsonl` must be valid UTF-8; a
non-UTF-8 log is a verify finding, not a traceback.

## Artifact fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `path` | string or null | yes | For a copied artifact, the relative slash-separated path under `D` (normally `artifacts/<prefix>-<basename>`). `null` only when `external` is true. Never absolute. |
| `source` | non-empty string | yes | Original file reference, relative to `D` and slash-normalized. Never absolute; may begin with `../` for a file outside `D`. |
| `bytes` | integer ≥ 0 | yes | Exact file size at recording time. |
| `sha256` | 64 lowercase hex characters | yes | SHA-256 of the exact file bytes. |
| `portable` | boolean | yes | `true` only for a copied artifact with a relative `path`. |
| `external` | boolean | yes | `true` for a reference recorded without copying. |
| `kind` | enum: `log`, `screenshot`, `report`, `note`, `dataset`, `other`, or null | yes (key present) | Optional operator label from the fixed v1 set; `null` when not supplied. Unknown values are rejected. |

### Copy and reference semantics

Default mode copies. The CLI resolves the supplied file, hashes it, and copies
it to `D/artifacts/<sha256-prefix>-<basename>` (12 hex characters; unsafe
filename characters replaced; re-copying identical bytes reuses the existing
destination). It records both the copied `path` and the original `source`.
`source` is the path relative to `D` when possible, otherwise a relative path
using `../`, or the basename when no relative path exists (for example a
different Windows volume). No absolute path is stored in the record.

`--external` hashes but does not copy. The entry has `path: null`,
`portable: false` and `external: true`, and `source` identifies the original
file. External entries are not portable; `verify` reports
`EXTERNAL/UNVERIFIED` and exits 1 unless `--allow-external` is given, and even
then the external bytes are not re-hashed.

Re-recording the same `source` replaces that entry. Copied files with a
different hash are added under a new name; superseded copies are not deleted by
the CLI.

### Path safety

For copied artifacts, `verify` rejects an absolute `path`, any `..` segment, any
symbolic-link component in the stored path, and any resolved target outside
`D`. A failed check is a finding and the exit code is 1. `source` is metadata
and is never opened by `verify`.

## Schema enforcement (schema-lite)

`verify` and `export` resolve `docs/aegis-run/schema.json` from the repository
root and load it on every invocation. If the file is missing or unreadable, both
commands fail closed with `SCHEMA_MISSING` and exit 1; they never fall back to
a looser shape. If it cannot be parsed, they fail with `SCHEMA_INVALID`.

The enforcement is a standard-library subset of JSON Schema: `required`,
`additionalProperties: false`, `properties`, `items`, `$ref`, `const`, `enum`,
`type` (including unions), `pattern`, `format` (`date-time`, `uuid`),
`minLength`, `minItems` and `minimum`. In record terms:

- The root must carry every required v1 field and no unknown field; `schema`
  must equal `aegis.run-record/1`.
- `created_at` must be an RFC3339 UTC timestamp ending `Z`; `run_id` must be a
  UUID; `app`, `aegis_commit` and `host` must be non-empty strings; a supplied
  `model` must be a non-empty string.
- Every event must carry `ts`, `type`, `stage`, `status`, `note` and `actor`, no
  unknown fields, an RFC3339 `Z` `ts`, a valid `type`/`status` enum, a non-empty
  `stage`, and string-or-null `note`/`actor`. The optional `source_id` must be a
  non-empty string matching `^SS-[0-9]{3,}$`, and `verify` additionally rejects
  it on any event whose `actor` is not `project-state-sync`.
- Every artifact must carry `path`, `source`, `bytes`, `sha256`, `portable`,
  `external` and `kind`, no unknown fields, a non-negative integer `bytes`, a
  64-lowercase-hex `sha256`, boolean `portable`/`external`, and a `kind` from
  the fixed enum or null. `path` is null only when `external` is true.
- `events` may be an empty array only before any event is recorded; `export`
  and `verify` require at least one event.
- `limitations` must be an array of non-empty strings; `export` and `verify`
  additionally require at least one entry.
- `outcome` must be `delivered`, `stopped` or `failed`; the schema permits null,
  but `export` and `verify` reject a record whose outcome is still null.

After schema enforcement, `verify` still re-hashes copied artifacts and checks
the manifest as described below. Schema acceptance is structural; it is not
identity or quality evidence.

## Manifest fields

| Field | Type | Meaning |
| --- | --- | --- |
| `schema` | const `aegis.run-manifest/1` | Manifest format and version. |
| `record` | const `aegis-run.json` | File name of the bound record in `D`. |
| `record_sha256` | 64 lowercase hex characters | SHA-256 of the exact `aegis-run.json` bytes written by `export`. |
| `artifacts` | array of `{path, source, bytes, sha256, portable, external}` | Projection of the record's artifact entries, same order, without `kind`. |

## Command semantics

1. `init` creates `D`, writes the record with empty `events`, `artifacts`,
   `limitations` and `outcome: null`, and creates an empty `events.jsonl`. It
   refuses to overwrite an existing record.
2. `event` appends the JSONL line and the mirrored event in that order.
3. `artifact` hashes and copies by default, or hashes and references with
   `--external`. A missing file is an error.
4. `finish` sets `outcome` and `limitations` once; a second call is an error,
   and at least one non-empty `--limitation` is required.
5. `sync` reads the project-state `## State snapshots` table under
   `D/sync.lock`, appends one event per unseen `source_id`, and prints one line
   per appended event plus a count. It writes nothing with `--dry-run`, and a
   missing file, section, header or malformed row is an error and exit 1.
   Every row ID is validated against `^SS-[0-9]{3,}$` before anything is written,
   so a bad ID cannot produce a partial import. `watch` polls that file and calls
   the same sync; `install-hook` writes `<repo>/.git/hooks/post-commit` (outside
   `D`), whose body changes directory to the named Aegis checkout and runs
   `PYTHONPATH=<checkout> python -P -m tools.aegis_run sync …` (`-P` without
   that `PYTHONPATH` does not import), so a repository-local `tools/` package
   cannot shadow it, and `uninstall-hook` removes only a hook carrying the
   aegis_run marker.
6. `export` loads the schema, requires a finished run, validates the record
   against the schema plus the non-empty `events` and `limitations` rules,
   rewrites the record canonically (atomic replace), then writes the manifest
   atomically with the hash of those exact record bytes, and prints both paths.
   A missing schema is `SCHEMA_MISSING`; invalid records are not written. JSON
   is deterministic: sorted keys, UTF-8, LF, trailing newline.
7. `verify` loads the schema (missing => `SCHEMA_MISSING`) and requires
   `aegis-run.json` and `manifest.json`. It enforces the loaded schema, including
   required fields, enums, RFC3339 `Z` timestamps, SHA-256 patterns, the
   `kind` enum, unknown-property rejection, at least one event, non-empty
   limitations, a final outcome and the `path`/`external` rule. It then checks
   the event log mirror (a non-UTF-8 log is a finding), each copied artifact
   exists as a regular file inside `D` with the recorded size and SHA-256 and
   without traversal or symbolic-link escape, and the manifest's schema, record
   name, `record_sha256` and artifact projection. Every finding is printed as
   `FAIL: ...` and the exit code is 1. With no findings it prints `PASS` and the
   scope block below, then exits 0.

Exit codes: `0` success/PASS, `1` record failure or verify FAIL, `2` argument
or usage failure.

## Verify scope

Every `verify` run prints:

```text
VERIFIED: record structure and copied artifact hashes only. NOT PROVEN: host/model identity, app correctness, security, delivery, universal support.
```

Exit 0 applies only to that scope. If `--allow-external` accepts external
references, the run prints an additional `EXTERNAL: N reference(s) ... remain
UNVERIFIED` line; those references are outside the verified scope.

## Claim limits

- **Single run.** A record is evidence about exactly one run identified by
  `run_id`, for one application, on one host, under one asserted
  `aegis_commit`. It says nothing about other runs, applications or commits.
- **Exact commit only.** `aegis_commit` is asserted text, not a signature and
  not validated against a repository. It does not prove the checkout matched
  that commit or that the commit exists.
- **Snapshots are not completion.** A synced event records the stage a
  project-state row named, with `status: started`. It is not evidence that the
  stage passed, finished, was reviewed, or was observed live; the older rows are
  explicitly labelled historical notes.
- **No universal claim.** PASS does not claim that Aegis works, that the
  application is correct, secure, complete or production-ready, that a stage
  passed for the right reason, or that every artifact was recorded. Absence of
  an artifact or event is not evidence of absence.
- **No certification or approval.** This tool grants no certification,
  compliance, readiness, delivery approval or merge permission, and is not a
  substitute for tests, independent review or owner sign-off.
- **Integrity, not identity.** SHA-256 detects changed bytes relative to the
  record for copied artifacts. It does not establish who wrote the record, that
  the record was not regenerated wholesale, or that `source` content still
  exists. There is no signature, key or trusted timestamp; all times are local
  clock values.
- **Verification is local and current.** PASS reflects the files at the moment
  `verify` ran, on that machine. It says nothing about later state.
- **External references are unverified.** A record with `external: true`
  entries is not portable; `--allow-external` only suppresses the failure, it
  does not verify the bytes.
- **Publication is the operator's responsibility.** Copying places bytes in
  `D/artifacts/` and `export` does not redact. Paths, notes, limitations, app,
  host, model and owner are published as entered.

## Privacy rules

- No network, credentials, provider calls or telemetry: the tool reads and
  writes the named run directory, the file supplied to `artifact`, the
  project-state file supplied to `sync`/`watch`/`install-hook` (read only), the
  checked-in `docs/aegis-run/schema.json`, and, only for `install-hook` /
  `uninstall-hook`, `<repo>/.git/hooks/post-commit` outside the run directory.
- Artifact bytes are copied into `D/artifacts/`, not embedded in the record.
  The record stores `path`, `source`, `bytes` and `sha256` only.
- No absolute path is stored. A `source` outside `D` is relative and may begin
  with `../`, which can reveal adjacent directory names.
- Keep publishable artifacts inside `D` so `source` stays internal.
- Do not put secrets, tokens, customer data or personal data in `--note`,
  `--limitation`, `--app`, `--host`, `--model` or `--owner`. There is no
  redaction step; scrub before recording.

## CI wiring: UNRUN

No workflow was added or edited. Wiring `verify` into CI would require a
protected workflow change and its own review. As delivered, CI wiring is
**UNRUN**; nothing in this contract claims CI enforcement.

## Compatibility

`schema` is a versioned string. A future incompatible change uses a new
identifier (for example `aegis.run-record/2`) and a matching schema file;
`verify` and `export` fail closed on an unknown schema or a missing schema
file. Additive optional fields may be declared in
[schema.json](schema.json) without a version bump; `additionalProperties` is
false, so consumers can rely on this field set.
