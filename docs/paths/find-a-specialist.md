# Find a specialist — name the situation, not the skill

*This path names who acts and in what order — each skill owns its own how.*

**Who this is for:** you can describe the situation in plain words but cannot name the skill for it — data and where it lives, documentation, analytics and experiments, planning for performance, core architecture and engineering, SaaS and tenancy, frontend craft, security and data protection, testing and quality, or simply "which skill should I use?". This page maps the situation to the specialist who owns it; you do not have to know its name first.

**How to run it:** open your project in your agent tool (Claude Code, OpenAI's Codex command-line interface (CLI), or any Agent Skills tool) and describe the situation in one plain sentence. Advisory specialists can be selected automatically; a specialist marked **manual-only** must be named explicitly by you before it runs (for a starter consumer, a valid trigger-scoped override recorded in the consumer-local register must cover it before use; naming alone is not authorization). For example: **"Reports are slowing down the app — which skill should I use?"** Auto-selection quality varies by tool; see the README's [tools section](../../README.md#using-aegis-with-codex-cli-and-other-agent-skills-tools).

**Before you start — what a starter install has.** The [starter package](../consumer-starter-package.md) installs none of these specialists (42 files / 19 skills; manual-only skills are not installed). Copy each skill you need with the **selected-skills allow-list** route in [Using the skills in your own project](../../README.md#using-the-skills-in-your-own-project): copy that skill's `.claude/skills/<name>/` folder into your repository, then check it is present at use time in `.claude/skills/<name>/`, `.agents/skills/<name>/` or `~/.agents/skills/<name>/`. For a starter consumer, record the extension as a DECISION in `docs/project-state.md` before first use (the starter §4.2 rule). If a skill is absent, name it and copy it — never substitute a different skill. Every handoff named in a row below is optional/conditional: copy the handoff skill first; if it is absent and you do not copy it, that route is unavailable and you can stop here. The starter package does not change for this page and there is no auto-install claim.

## The situation map

### Data and where it lives

| The situation, in plain words | Who owns it (and its rules) |
|---|---|
| "I need to change a table or schema without breaking the live app." | [`schema-evolution-planner`](../../.claude/skills/schema-evolution-planner/SKILL.md) — stages the change while the system keeps serving traffic; it refuses a one-deploy breaking change and stops when the consumer list cannot be completed. The migration file's safety review is [`secure-migration-reviewer`](../../.claude/skills/secure-migration-reviewer/SKILL.md); the operator steps are [`data-migration-runbook-author`](../../.claude/skills/data-migration-runbook-author/SKILL.md) — copy it first (the starter does not install it). |
| "I need step-by-step instructions to move or backfill data in production." | [`data-migration-runbook-author`](../../.claude/skills/data-migration-runbook-author/SKILL.md) — authors the operator-executable runbook and refuses to execute it; it stops without an approved plan, a safety-review verdict and a **verified restore-test record** (a manual-only backup-verification step invoked by a human, or an equivalent restore-test record). |
| "Reports are slowing down the app." | [`operational-vs-analytical-splitter`](../../.claude/skills/operational-vs-analytical-splitter/SKILL.md) — decides the split and executes nothing; one slow query with a broken plan goes to [`query-plan-reader`](../../.claude/skills/query-plan-reader/SKILL.md) **manual-only — name it explicitly** first, and a workload with no freshness tolerance holds its verdict. |

| "Services need to pass events to each other reliably." | [`streaming-event-architect`](../../.claude/skills/streaming-event-architect/SKILL.md) — designs internal event transport; a partner/public contract routes to the external API-contract owner (not this internal-event designer), and a hard exactly-once requirement goes to a human with the honest options. |
| "We need to know when data goes bad in production." | [`data-quality-monitor-designer`](../../.claude/skills/data-quality-monitor-designer/SKILL.md) — designs monitoring and executes nothing; it refuses silent auto-repair, and unsourced validity rules stop that dataset. |
| "Where does personal data live, and how do we delete it everywhere?" | [`pii-lifecycle-designer`](../../.claude/skills/pii-lifecycle-designer/SKILL.md) — designs the collection, classification, retention and deletion model; it refuses an "anonymized" label without a re-identification check, and it may not read bulk actual personal values. |

## What this is — and isn't

This is a guided map, not a guarantee: each specialist owns its own how, its own preconditions and its own stop conditions, and the named skill's own text governs when it runs. Several of the skills above are design or advisory only — they produce a plan, finding or recommendation and execute nothing.

The starter package installs **none** of these specialties; a missing skill is copied through the selected-skills route or that step stops. Manual-only specialists are never auto-applied: you name the exact skill and invoke it yourself. Nothing on this page fixes anything during a mapping.

There is no readiness claim, no coverage-percentage claim, no host-support claim and no eval-detection claim here. The shortlist row depends on the catalog and manifest, which a starter copy may not carry, so it can stop short of a definitive answer rather than invent one.

Nothing here is a conductor: the whole journey belongs to `project-orchestrator`. For a symptom that is already broken, use the symptom map in [Something's broken](something-is-broken.md); for a ranked shortlist for a stated outcome, use [`skill-selection-advisor`](../../.claude/skills/skill-selection-advisor/SKILL.md).
