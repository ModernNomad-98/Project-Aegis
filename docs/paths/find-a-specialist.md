# Find a specialist — name the situation, not the skill

*This path names who acts and in what order — each skill owns its own how.*

**Who this is for:** you can describe the situation in plain words but cannot name the skill for it — data and where it lives, documentation, analytics and experiments, planning for performance, core architecture and engineering, SaaS and tenancy, frontend craft, security and data protection, testing and quality, operating and governing agent work, or simply "which skill should I use?". This page maps the situation to the specialist who owns it; you do not have to know its name first.

**How to run it:** open your project in your agent tool (Claude Code, OpenAI's Codex command-line interface (CLI), or any Agent Skills tool) and describe the situation in one plain sentence. Advisory specialists can be selected automatically; a specialist marked **manual-only** must be named explicitly by you before it runs (for a starter consumer, a valid trigger-scoped override recorded in the consumer-local register must cover it before use; naming alone is not authorization). For example: **"Reports are slowing down the app — which skill should I use?"** Auto-selection quality varies by tool; see the source-only Aegis README's tools section.

**Source-only links.** Links to skills or pages outside the starter package are source-repository links; in a consumer copy they do not resolve — copy the skill first (starter sections 4.1–4.2).

**Before you start — what a starter install has.** The starter package installs **at most `skill-selection-advisor`** from this guide's specialists (some starter versions install it and others do not); check `.claude/skills/skill-selection-advisor/` at use time. None of the other specialists is installed, and manual-only skills are not installed. Copy each skill you need with the **selected-skills allow-list** route in the source-only `README.md` section "Using the skills in your own project": copy that skill's `.claude/skills/<name>/` folder into your repository, then check it is present at use time in `.claude/skills/<name>/`, `.agents/skills/<name>/` or `~/.agents/skills/<name>/`. For a starter consumer, record the extension as a DECISION in `docs/project-state.md` before first use (the starter §4.2 rule). If a skill is absent, name it and copy it — never substitute a different skill. Every handoff named in a row below is optional/conditional: copy the handoff skill first; if it is absent and you do not copy it, that route is unavailable and you can stop here. The starter package does not change for this page and there is no auto-install claim.

## What this is — and isn't

This is a guided map, not a guarantee: each specialist owns its own how, its own preconditions and its own stop conditions, and the named skill's own text governs when it runs. Several of the skills above are design or advisory only — they produce a plan, finding or recommendation and execute nothing.

The starter package installs **at most `skill-selection-advisor`** from these specialties (some starter versions install it and others do not; check `.claude/skills/skill-selection-advisor/` at use time); the rest are missing until copied through the selected-skills route or that step stops. Manual-only specialists are never auto-applied: you name the exact skill and invoke it yourself. Nothing on this page fixes anything during a mapping.

There is no readiness claim, no coverage-percentage claim, no host-support claim and no eval-detection claim here. The shortlist row uses the manifest and the source catalog; a starter copy may carry the manifest but not the catalog, so the advisor uses its catalog-missing fallback and can stop short of a definitive shortlist.

Nothing here is a conductor: the whole journey belongs to `project-orchestrator`. For a symptom that is already broken, use the symptom map in [Something's broken](something-is-broken.md); for a ranked shortlist for a stated outcome, use [`skill-selection-advisor`](../../.claude/skills/skill-selection-advisor/SKILL.md).
