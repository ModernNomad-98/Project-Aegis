**The backing corpus is committed beside this record:
`.coord/proc08-sweep-manifest.tsv`** — one row per enumerated branch, tab separated:
`branch`, `tip_sha`, `pr_count`, `exit_status`. **The totals in §4 are re-derived
from that file rather than asserted**, and the re-derivation is four counts over

```
$ awk -F'\t' '!/^#/' .coord/proc08-sweep-manifest.tsv | wc -l              # branches      -> 612
$ awk -F'\t' '!/^#/ && $3>0' .coord/proc08-sweep-manifest.tsv | wc -l      # with a PR     -> 606
$ awk -F'\t' '!/^#/ && $3==0' .coord/proc08-sweep-manifest.tsv | wc -l     # empty         ->   6
```

run without it, `$4!=0` compares an empty field against `0`, which awk evaluates as a
string comparison and counts as true — so the non-zero-exit count reads **7** (the
seven comment lines) instead of **0**. The filter was added after running the
commands literally, not before.

## 6. What this run establishes about the rule itself

The landed line claims, and the register repeats at `:2440-2442`:

> **The detector is complete over the refs it reads** — the branch itself is the
> readable artifact, so an empty result is a real finding

**Running it once shows that claim is not accurate as landed.** "Complete over the
refs it reads" is true of the *enumeration* — every head is read — but the
*verdict* "empty result = real finding" is false for at least two classes of head
that the step does not exclude:

1. the **default branch**, which is in the enumerated set and which can never have
   a pull request, so it is reported on every run; and
2. a branch whose tip is **already contained in the default branch**, which is
   reported as unproposed work although no work is outstanding.

Two of the six hits this run are of those classes. Neither is a defect in the work;
both are defects in the detector's *claim*. The step remains executable and still
finds real candidates — it is not unexecutable — but a cadence check that reports a
permanent false positive will train its reader to ignore it, which is the failure
mode the step exists to prevent.

**Recorded, not patched.** Changing the detector's text is an edit to a landed
process rule and belongs to the owner, not to this run.
